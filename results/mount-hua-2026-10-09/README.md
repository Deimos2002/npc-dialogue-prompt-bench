# Development benchmark evidence

Two live v4 runs: Qwen through Groq and Gemini, three prompt strategies each.
Each run includes 42 visible replies, 28 plans and its recorded input hashes.
Both canonical runs replay exactly from the repository root without keys.

See [the evaluation](../../docs/pilots/mount-hua/benchmark-2026-10-09.md) for
settings, findings, denominators and limitations. `review/measurements.json`
is generated by `scripts/summarize-pilot.py` from each canonical recordings file.

`allocation-transcriptions.json` contains the assistant's transcription of
sixty exact-allocation tasks in S/A/V/Q order, keyed to recordings. Zeros are
inferred only where the entire pool is assigned elsewhere. A null entry means
the reply omitted an exact split. The assistant inspected all visible replies;
these are not independent human labels.

`rubric-review.csv` evaluates those sixty tasks for arithmetic and draft
relative priorities, with other turns marked outside that quantitative subset.
It also records the six missing-context replies and composure across six
three-turn insult conversations. Semantic observations and repetition are
documented in the evaluation rather than reported as a comprehensive grounding
pass rate. This CSV is the custom pilot worksheet, not an import file for
`bench adjudicate`. The application's pending semantic verdicts remain pending.

Shuffled review worksheets hide strategy labels and system instructions, but
the assistant already knew the prompts and saw some identified replies during
collection. This was not a fully blinded review. Identity maps support later
independent review; retain player history when assessing state tracking.

Recordings contain fictional prompts and generated text, not API keys or
authorization headers. Preserve the original input files for replay.
